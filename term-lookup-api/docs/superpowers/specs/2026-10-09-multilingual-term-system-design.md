# 多类型多语言词条系统设计

2026-10-09：用户确认开始实施。

## 目标和边界

在现有 Node.js + SQLite API 中补齐多语言详细描述、富文本正文、摘要、封面、来源、子词条列表、完整祖先路径、标签、分类、词条类型、别名和同义词。面向人物、作品、地点、组织、专业术语等多种内容。交付可用的服务端 API、迁移、回归测试和使用文档；当前模块没有前端，本轮不新增管理界面或文件上传服务。

## 架构选择

推荐使用版本化的 `/v2` 契约，将多语言名称统一为数组，并提供按 ID 的显式更新。既有 `/v1` 保留单字符串名称和英文 upsert 契约，作为兼容适配层；同名导致无法确定目标时拒绝覆盖。数据库共用，迁移保留所有旧词条 ID、名称、父级与时间戳。

只给 `/v1` 增加零散字段会保留按英文覆盖和更新时清空父级等不适合内容管理的行为；另建服务会增加部署及数据同步成本。本方案在现有模块内升级。

## 词条契约

```json
{
  "type": "character",
  "translations": {
    "en": ["Raiden Shogun", "Ei"],
    "zh-Hans": ["雷电将军", "雷电影"]
  },
  "details": {
    "zh-Hans": {
      "summary": "角色简介",
      "description": "用于检索或纯文本展示的详细描述",
      "body": "## 详细介绍\n\n正文、列表、表格与链接。",
      "format": "markdown"
    }
  },
  "cover": {"url": "https://example.com/cover.jpg", "alt": {"zh-Hans": "角色封面"}},
  "sources": [{"url": "https://example.com/source", "title": "资料来源", "language": "zh-Hans"}],
  "parentId": 1,
  "tagIds": [1],
  "categoryIds": [2]
}
```

- `translations` 是语言标签到名称数组的映射；`en` 和 `zh-Hans` 必填，第一项是首选名，其余是同义词/别名。所有名称可精确检索，统一使用 NFKC、trim 和现有小写化规则。保留大小写用于展示。语言标签规范化，避免 `en` 与 `EN` 分裂。
- `type` 对应已存在的类型；内置 `term`、`person`、`character`、`work`、`place`、`organization`、`item`，允许维护自定义类型，旧数据默认 `term`。
  默认 `term` 类型不能删除或更改 slug，以保证默认创建和 v1 兼容；展示名允许修改。
- `details` 按语言维护，名称与正文语言不必完全一致。`summary`、`description` 是纯文本，`body` 是 Markdown 富文本源文。字段为空字符串表示清空。
- 支持安全富文本渲染：标题、强调、列表、引用、表格、代码块、链接和图片。默认禁用原始 HTML，过滤危险 URL 协议；渲染结果经过 HTML 白名单清洗。正文既能取回原始 Markdown，也能通过内容接口取得安全 HTML。
- `cover` 可为 `null`；URL 仅允许 HTTPS/HTTP，`alt` 为多语言文本。来源数组包含 URL、标题、可选语言；服务只保存引用，不主动抓取来源或下载封面。
- `parentId` 可为 `null`，每条词条最多一个直接父级，允许跨类型归属。祖先按根到直接父级排序，不含当前词条。禁止自引用和循环。
- `tagIds` 和 `categoryIds` 多对多、去重、必须引用存在记录。分类与词条归属是独立层级：作品归属与主题分类可以并存。
- 响应包含 ID、创建/更新时间、父级摘要、完整祖先摘要、类型、标签和分类摘要。列表省略正文；详情返回完整字段。

## 同名词条与检索

允许不同词条在同一语言使用相同名称，适用于多个作品中的同名人物。同一词条、同一语言内禁止规范化后重复名称。

`GET /v2/terms?q=...&from=...` 返回分页候选列表；可以用 `type`、`parentId`、`tagId`、`categoryId` 筛选。同义词与首选名享有相同检索地位。`to` 可选，指定时每项返回目标语言名称数组，没有对应语言则为 `null`。

名称匹配默认采用现有精确规范化规则。本轮不增加模糊匹配和全文搜索。候选结果按 ID 稳定排序，默认每页 20 条，最多 100 条。分页返回 `items`、`total`、`limit`、`offset`。

## API

所有写入接口沿用 API Key/Bearer 鉴权。按用户后续要求，v1/v2 GET 搜索与读取可匿名访问；同 IP 滚动60秒共享20次额度，有效 Key 不限流。错误 Key 返回401，超限返回429并附 Retry-After。health 保持公开不限流。默认使用连接 IP，仅显式 TRUST_PROXY_IPS 指定代理的 X-Forwarded-For 可参与客户端 IP 解析。

| 接口 | 行为 |
| --- | --- |
| `POST /v2/terms` | 仅创建，返回 201，不因名称重复覆盖已有内容 |
| `GET /v2/terms` | 分页查询与筛选，无 q 时列出词条 |
| `GET /v2/terms/:id` | 获取完整词条与祖先路径 |
| `PATCH /v2/terms/:id` | 更新指定字段；省略保持原值，父级/封面 null 表示清空 |
| `DELETE /v2/terms/:id` | 无子词条时删除；存在子词条返回 409，不级联删除内容 |
| `POST /v2/terms/:id/names` | 按 language/value 追加别名；同词条重复追加幂等 |
| `DELETE /v2/terms/:id/names` | 按 language/value 删除别名；不得删除必填语言的最后一个名称 |
| `GET /v2/terms/:id/children` | 直接子词条分页列表 |
| `GET /v2/terms/:id/ancestors` | 根到直接父级的完整摘要路径 |
| `GET /v2/terms/:id/content?language=...` | 原始多语言内容及清洗后的 HTML；未维护的语言返回 404 |
| `GET/POST /v2/types` | 列出/创建类型 |
| `PATCH/DELETE /v2/types/:id` | 修改类型展示名；被词条引用时禁止删除 |
| `GET/POST /v2/tags` | 列出/创建多语言标签 |
| `PATCH/DELETE /v2/tags/:id` | 修改标签；删除同时解除词条标签关联 |
| `GET/POST /v2/categories` | 列出/创建多语言分类，支持 parentId 筛选 |
| `PATCH/DELETE /v2/categories/:id` | 修改分类及父级；存在子分类或词条引用时禁止删除 |

类型、标签、分类均有稳定 ID、唯一 slug 和多语言名称；类型 slug 同时是词条 `type` 的输入值。分类支持单父级、循环保护与祖先路径。标签没有父级。

PATCH 的 `details` 按语言合并、每个语言内按字段合并；`details.<language>: null` 删除该语言内容。translations 提供时替换完整名称映射；sources/tagIds/categoryIds 提供时替换对应集合。parentId 省略保留，null 清空。所有修改在单个事务内完成，任何校验失败都不部分写入。

## 兼容和迁移

既有 v1 输出继续是语言到字符串的映射，取 v2 名称数组首项；v1 精确查找也可以命中别名。命中多个词条返回 `409 ambiguous_term`，不能随意返回第一条。既有唯一名称场景行为不变。

v1 upsert 只在英文精确匹配到唯一的 `term` 类型词条时更新；多个匹配或只命中其它类型时返回 409。v1 更新不覆盖新的内容、封面、来源和分类；保留既有 v1 的父级省略即清空行为，README 标明管理端应使用 v2 PATCH。旧测试继续覆盖 v1；新增测试覆盖 v2。

新版本迁移在事务内重建名称索引，解除全库名称唯一限制，增加词条内容、分类/标签关系和类型表。逐条校验旧 JSON，遇到损坏数据回滚，不能静默删除。保留从旧版本升至当前版本的迁移测试；重复迁移幂等。未知未来 schema 版本应拒绝启动。

历史版本合法的长名称、语言标签或大小写语言键不应阻断升级。迁移保留长名称，规范化可识别的标签，将大小写语言键合并为名称数组；旧正则允许但 Intl 不识别的标签保留并可用 v1 查找。新增名称按 v2 规则校验，不能要求用户先删掉已有历史例外；删除历史名称允许原有长度和标签。完整替换名称集合使用新规则。v1 冲突检查仅针对本次提交名称，不因未修改的历史共享别名阻断更新。

## 校验与资源限制

- v1 保留 64 KiB 请求体限制；v2 上限 2 MiB；正文按 UTF-8 每语言最多 512 KiB，所有内容仍受总请求体上限约束。
  合并后的词条可写字段总大小也限制为 2 MiB，防止多次 PATCH 累积绕过总大小限制。
- 每语言最多 50 个名称，每个名称最多 256 字符；最多 50 个语言。
- summary 最多 2,000 字符；description 最多 20,000 字符；URL 最多 2,048 字符。
- 每条最多 100 个来源、100 个标签和100 个分类。slug 使用小写字母、数字与连字符，1–64 字符。
- 拒绝未知写入字段、非法语言标签、错误字段类型、无效关联、重复名称和非法 URL。允许 http/https 图片链接，禁止 javascript/data 等协议。
- 查询参数与分页严格校验；id 为正安全整数。非法输入返回 400，鉴权失败 401，不存在 404，关系冲突 409，超限 413，存储异常 500。错误内容不得暴露 SQL 或密钥。
