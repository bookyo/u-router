# RO 商人商店面板（浏览器插件）v2

游戏页右侧悬浮「蝎子商人」商店面板：实时目录 / 总价 / 一键自动交易。
与 `ro-unsticker-extension` 同骨架（MAIN 世界注入 + ISOLATED 桥），可共存。

## v2 重大变更（2026-09-21，用户实测反馈驱动）

| 问题 | v1 行为 | v2 修复 |
|---|---|---|
| 移动/交易后**被服务器踢线** | 封包直发（自算密钥流重放） | **彻底移除封包注入**，改为**驱动游戏自己的 DOM 界面**（客户端自行加密，密钥流永不错位） |
| 面板点击穿透到游戏（点地面走人/打字触发快捷键） | 事件冒泡到 document | 面板根节点拦截全部鼠标/滚轮/键盘事件 `stopPropagation()` |
| 面板不能缩小 | 只有 ✕ | 标题栏加「−」折叠按钮 |
| 目录什么都有 | 全部库存上架 | **仅显示已定价商品**；未定价=非卖品（服务端 /stock 过滤 + /order、/trade 双重拒售 403） |
| 下单报 buyer 不在身边 | 仅按名字匹配实体 | 请求携带 `window.aid`/`window.gid`，商人端**四路匹配**（名字/aid/gid × GID/AID 字段） |

### 踢线根因（2026-09-21 抓包实证，ro-wslog-2026-09-21-05-02-10.json）

浏览器客户端的发送加密是**逐包推进的真流式密钥**（2-adic LCG，约 16+ 包后才收敛到不动点 0x5945）。
任何外部注入都会让服务器密钥流比客户端多走一步 → 客户端下一个包掩码错位 → 服务器读到乱码 pid → 踢线。
node 机器人无此问题是因为它自己收敛了流；浏览器端唯一安全的做法是**不注入，让客户端自己发**。

### v2 自动交易链（全程 DOM 驱动）

1. 面板点「🤝 发起交易」→ `POST /trade {buyer, name, qty, aid, gid}`（商人主动发起）
2. 300ms 轮询：交易请求弹窗 `#WinPrompt`（文本含「蝎子商人」）→ 自动点第一个按钮（确定=0x00E6 result3）
3. `#Trade` 窗出现 → 填 `input.zeny.send` = 总价 → 点 `.btn.ok.enabled`（**官方 onConclude 会自动 addExchange(0,金额) 再锁定**，与手输完全一致）
4. 商人验钱通过锁定后 `.btn.trade.enabled` 亮起 → 自动点击（0x00EF 执行）
5. `#Trade` 关闭 → `GET /lasttrade` 判定成交/取消 → toast
6. 90s 总超时；路人的 WinPrompt（文本不含商人名）不会被误点

## 安装

1. Chrome 打开 `chrome://extensions` → 开发者模式 → 加载已解压的扩展程序 → 选本目录
2. 刷新游戏页（post.lastro.cn/ro/api.html），右侧出现「🛒 蝎子商人」面板（可拖动、− 折叠）

## 使用

1. 面板自动拉取在售商品（15s 刷新；需要本机 mule.js 在 127.0.0.1:8790 运行）
2. **自行走到商人旁**（梦罗克 181,85；v2 移除了代步按钮——见上表）
3. 点选商品 → 调数量（超库存红字、缺货置灰）→ 点「🤝 发起交易」→ 之后全自动

## 商人端配套（mule.js）

- `/stock` 仅含有价商品；`/order`、`/trade` 拒售未定价（403 not for sale）
- `/trade` 买家实体四路匹配（名字/aid/gid）
- `/lasttrade` 返回最近一单结果 `{ok, at, from}`（面板判定成交/取消）
- 定价：`POST /price {name, price}`（改 `data/mule-prices.json`）

## 已知限制

- 代步（飞艇/寻路）按钮 v2 暂移除：封包直发必踢线，等改用世界地图/画布 UI 驱动后再加回
- QQ 群友使用需商人 API 暴露公网（当前 127.0.0.1 仅本机）；挂到带反代的域名后改面板 MULE 地址即可
